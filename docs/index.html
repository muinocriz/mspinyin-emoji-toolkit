现象：Win + . 搜索“水桶”可以找到 🪣；微软拼音输入 shuitong 却没有。

调查得到的核心结论

问题不是字体缺失，也不是简单的联网搜索差异，而是 Windows 同时维护了两套用途不同、生命周期不同的 Emoji 检索路径。

96.4%这类 Emoji 记录直接携带 slot 5

我们是怎么找到它的

调查并不是从 `ChsPinyinUDP.lex` 直接开始，而是先排除用户自定义短语和个人学习数据，再把范围缩小到系统输入法资源。

01

UserDefinedPhrase.dat / mschxudp

先确认用户自定义短语可以保存 shuitong → 🪣。它证明 Emoji 能被当作 UTF-16LE 候选字符串，但不能证明系统内置 Emoji 就存在用户短语中。

02

解码 UDL / IH / DeletedCands

ChsPinyinUDL.dat 保存自学习词条和拼音索引；ChsPinyinIH.dat 保存历史/计数型记录；DeletedCands 是不透明的 8-byte 内部记录。扫描后没有发现系统 Emoji 映射。

03

转向 Windows 系统词典

对主词典、语言模型、额外资源、预测词典和热词索引逐个做签名、字符串、熵和 Emoji surrogate pair 检查。

04

锁定 ChsPinyinUDP.lex

该文件可以直接结构化得到 huoyan → 🔥、xiaoku → 😂、aini → 😘 等映射，成为决定性证据。

为什么说内容在 2017 出现断层？

按“当前带 Emoji property 的 code point 最初进入哪个 Unicode 版本”统计，本机 UDP 对 Unicode 10 的新增覆盖很高，但 Unicode 11 起直接降到 0。

这描述的是词库内容年代，不是文件打包时间。样本文件头仍可对应到 2025 年，说明资源可能继续被重新打包，但 Emoji 集合没有同步扩充。

ChsPinyinUDP.lex 大概长什么样

它属于 `mschxudp` 家族：64-byte header + uint32 offset table + 变长 UTF-16LE 记录。

0x0000  64-byte header
0x0040  uint32 record_offsets[count]
        ↓
        variable-length records

record:
+0x00  uint32   record_magic
+0x04  uint16   text offset
+0x06  uint8    candidate_slot
+0x07  uint8    flags_byte
+0x08  uint32   type_id
+0x0C  uint32   record_timestamp
+0x10  UTF-16LE py   + 00 00
...    UTF-16LE text + 00 00

新增普通 Emoji 的保守默认

candidate_slot   = 5
record_magic     = 1048592  # 0x00100010
flags_byte       = 19       # 0x13
type_id          = 6
record_timestamp = 724750598

这些值来自现有记录分布。`type_id=6` 不应被写成微软官方定义的“Emoji 类型”，内部业务命名仍未知。

一个实机细节：写拼音，不要写中文触发词

CSV 输入码py = niubi
→
候选字符串
🐮🍺

`py` 是 IME 匹配的输入码字符串，不是自然语言关键词。因此写 py=牛比 是错误思路。`text` 则是 UTF-16LE 字符串，可以包含多个 Emoji、ZWJ 序列，甚至 Emoji + 普通文字。

已经形成的工具链

项目不只记录逆向结论，也提供可复现的解析和回写脚本。

MSPinyinUDP_LEX_to_CSV.py

把系统 UDP LEX 完整导出为可编辑 CSV。

MSPinyinUDP_CSV_to_LEX.py

从 CSV 重建 LEX，自动按 `py` 排序并报告新增记录位置。

MSPinyinUDP_verify.py

验证结构、记录数和关键字段。

MSPinyinUDL_to_CSV.py

解码 UDL 自学习短语、拼音索引和时间字段。

MSPinyinIH_to_CSV.py

导出输入历史/学习计数型记录。

MSPinyinDeletedCands_dump.py

保守导出 DeletedCands 的不透明内部记录。

可逆性验证：原始样本执行 LEX → CSV → LEX，在 CSV 未修改时重建文件与原文件 SHA256 完全一致，达到 byte-for-byte identical。实机测试还确认：替换系统 LEX 后，从英文输入法切回微软拼音，新加入的映射即可生效，无需重启整台电脑。

注意：系统文件替换涉及 TrustedInstaller 权限，Windows Update / SFC 也可能恢复系统资源。项目报告保留了备份、临时提权、恢复所有者和 PowerShell 常见错误的完整操作记录。实机结论仅代表本次测试版本，不保证所有 Windows 构建行为一致。
